## Context

AXIMUX-0002 shipped a pinctrl driver but could not be compiled/verified on the author host (no kernel headers). Aggressive validation needs a guest with matching kernel ABI and programmable MMIO.

Board deploy (2026.1 scarthgap) provides Linux **6.18.10** for **armv7 / Zynq-7000** (not aarch64). Use upstream QEMU 11.x (not stale classroom trees).

## Decision

Validate the pinctrl driver on **qemu-system-arm -M virt** with:
1. Kernel **6.18.10** (`multi_v7`) from scarthgap `kernel-source`.
2. Custom QEMU `aximux` sysbus device at `0x090d0000` (MUXINFO + SRCSEL).
3. Minimal busybox initramfs + automated guest checks.
4. DT node `brunosmmm,aximux-2.0` generated by virt.

## Design (shipped)

| Path | Role |
|------|------|
| `sim/qemu/hw/aximux.c` | QEMU MMIO model |
| `sim/qemu/scripts/{build-qemu,build-guest,run-test,patch-virt}.sh` | Host flow |
| `sim/qemu/guest/init.sh` | Guest: insmod → pinmux-select → srcsel |
| `make test-qemu` | Top-level entry |

Driver fix for unique pin names: DT `pin@N` children now register as `pinN` (OF `name` is only `"pin"`).
